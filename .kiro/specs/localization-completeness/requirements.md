# Requirements Document

## Project Description (Input)
表示言語の翻訳キーの欠落を解消し、`LanguageKey` と全13言語の言語ファイル（YAML）の網羅を機械的に検証する仕組みを設ける。

**誰の問題か**: Large Folder Finder の開発者（個人開発、単独）と、英語・日本語以外の11言語で本アプリを使う利用者。

**現状**: `Services/LocalizationManager.cs` の `LanguageKey` 列挙は81キーを定義している（2026-09-17 確認。brief 作成時の80から1つ増えている）。`Resources/Languages/` の en と ja は81キーすべてを持つが、他の11言語（de, es, fr, hi, it, ko, pt-BR, ru, tr, zh-CN, zh-TW）は79キーで、`HeaderOwner`（一覧の所有者カラムの見出し）と `ContextShowOwner`（右クリックメニューの項目）が欠けている。言語ファイルにだけ存在するキーはない。`GetText` は見つからないキーを英語に置き換えるため例外にならず、11言語では該当箇所だけ英語が表示される。この欠落は例外にもならず、目視でも気づきにくいため構造的に発覚しない。キーの網羅を検証する仕組みは存在しない。また `LanguageKey` の宣言コメントは「YAML ファイルと順序を一致させること」と書くが、実装はキー名で辞書を引いており順序に依存しないため、コメントが実装と食い違っている。

**何が変わるべきか**: 13言語すべてが `LanguageKey` の全キーを持つ。キーの欠落（および言語ファイルにだけあるキー）が機械的に検出され、キーを追加して一部の言語に反映し忘れた場合に、検証の実行で気づける。宣言コメントが実装と一致する。

**制約**: .NET 10 移行の前後どちらでも成立し、移行後に捨てる実装を作らない。テストプロジェクトが未整備でも動き、移行後にテストへ引き上げられる形にする。訳語は各言語の既存の同種キー（カラム見出し、右クリックメニュー項目）と語調をそろえる。単位名（KB・GB など）は訳さないと決めた例外がある（`.kiro/steering/decisions.md`）。新しいラベルの追加、対応言語の増減、ローカライズ機構の作り替え、既存訳文の見直しは範囲外。詳細は [brief.md](brief.md) を参照。

### 前提と決定事項

- **欠落の知らせ方**（2026-09-17 利用者の決定）: 欠落があってもアプリのビルドは止めない。検証は開発者が別に実行するものとし、後に CI（`dotnet10-migration` が整える GitHub Actions）から自動実行できる形にする。理由は、翻訳を後回しにした状態でもビルドと動作確認を止めないため
- **差し込み位置のずれを扱う**（2026-09-17 利用者の決定。brief の「既存訳文の見直しは範囲外」に対する例外）: 要件作成時の調査で、スキャン中の状態表示に使う `TimeStatusFormat` が、en と ja では `"{0} {1}"`（経過時間と残り時間）なのに対し、他の11言語では `{1}` を持たず、**11言語でスキャン中の残り時間が表示されていない**ことが分かった。キーの欠落と同じく例外にならず気づけない種類の不具合であるため、訳文の差し込み位置を直し、ずれを検証でも検出する。同じ調査で、画面から使われていない `LiveScanningMessage` でも ja と ru の差し込み位置がずれていた（実害はない）。重複キーと空の訳文は0件だった
- 言語ファイルの構文が壊れている、またはキーが重複していて読み込めない場合、アプリはその言語のすべての表示を英語に置き換える。これも同じ種類の不具合として検証の対象に含める

## Introduction

本フィーチャーは、Large Folder Finder の表示言語について、**翻訳の抜けとずれが黙って英語表示や表示の欠けに化ける**状態を解消するものである。

現状の欠陥（11言語で2キーが欠落、11言語で残り時間の差し込み位置が欠落）をデータとして直したうえで、同じ種類の欠陥が再び入り込んだときに開発者が機械的に気づける検証を設ける。検証の対象は、アプリに同梱される言語ファイルのすべてである。アプリの読み込みや英語への置き換えの挙動そのものは変えない。

## Boundary Context

- **In scope**: 11言語への `HeaderOwner` と `ContextShowOwner` の訳文の追加、差し込み位置が英語とずれている訳文の修正、言語ファイルのキーの網羅・孤児キー・差し込み位置・読み込み可否の検証、`LanguageKey` の宣言コメントの実態への修正
- **Out of scope**: 新しい UI ラベルの追加（`ui-redesign`）、対応言語の追加・削除、ローカライズ機構の作り替え（`architecture-refactoring`）、差し込み位置以外の既存訳文の見直し、使われていないキーの削除、`Readme/Readme_{lang}.txt` など言語ファイル以外の多言語資料、検証の CI への組み込み（`dotnet10-migration`）、欠落時にビルドを失敗させること
- **Adjacent expectations**: `dotnet10-migration` が整えるテスト基盤と CI から、本フィーチャーの検証を呼び出せることを期待する。`ui-redesign` はラベルを追加する際に本フィーチャーの検証を通すことを前提とする

## Requirements

### Requirement 1: 全言語のキーの充足

**Objective:** As a 英語・日本語以外の言語の利用者, I want すべての表示が選んだ言語で出ること, so that 一部の項目だけ英語が混ざらずに操作できる

#### Acceptance Criteria

1. The Large Folder Finder shall 同梱するすべての言語ファイルに、`LanguageKey` が定義するすべてのキーの訳文を持つ
2. While 表示言語が英語以外に設定されている, when 利用者が一覧の所有者カラムを表示したとき, the Large Folder Finder shall カラムの見出しをその言語の訳文で表示する
3. While 表示言語が英語以外に設定されている, when 利用者が一覧の右クリックメニューを開いたとき, the Large Folder Finder shall 所有者の表示を切り替える項目をその言語の訳文で表示する
4. The Large Folder Finder shall 追加する訳文の用語と語調を、同じ言語の同種の既存項目（一覧のカラム見出し、右クリックメニューの項目）とそろえる

### Requirement 2: 差し込み位置の一致

**Objective:** As a 英語・日本語以外の言語の利用者, I want スキャン中に経過時間と残り時間の両方が見えること, so that 英語・日本語の利用者と同じ情報で待ち時間を判断できる

#### Acceptance Criteria

1. While スキャンが進行中で残り時間の見込みが算出されている, the Large Folder Finder shall 13言語のいずれにおいても、状態表示に経過時間と残り時間の両方を表示する
2. The Large Folder Finder shall すべての言語ファイルのすべての訳文について、値が差し込まれる位置の番号の組を英語の訳文と一致させる
3. When 差し込み位置のずれを修正するとき, the Large Folder Finder shall 差し込み位置を補う・直すために必要な範囲を超えて訳文の言い回しを変えない
4. The Large Folder Finder shall 単位名（KB・GB など）を訳さないという既存の決定に反する訳文を、差し込み位置の修正によって新たに作らない

### Requirement 3: 網羅の検証

**Objective:** As a 開発者, I want 翻訳の抜けとずれを機械的に見つけられること, so that 例外にも目視にも引っかからない欠陥を出荷前に直せる

#### Acceptance Criteria

1. When 開発者が検証を実行したとき, the 網羅性検証 shall 同梱対象の言語ファイルすべてを対象に、`LanguageKey` の各キーの訳文が存在するかを調べる
2. If ある言語ファイルに `LanguageKey` のキーの訳文が存在しないとき, then the 網羅性検証 shall その言語とキーの名前を報告する
3. If ある言語ファイルに `LanguageKey` に定義されていないキーが存在するとき, then the 網羅性検証 shall その言語とキーの名前を孤児として報告する
4. If ある言語ファイルの訳文の差し込み位置の番号の組が英語の訳文と異なるとき, then the 網羅性検証 shall その言語、キーの名前、英語側と当該言語側の差し込み位置を報告する
5. If ある言語ファイルがアプリと同じ規則で読み込めないとき（構文の誤り、キーの重複を含む）, then the 網羅性検証 shall その言語を読み込み不能として理由とともに報告し、残りの言語の検証を続ける
6. When 問題が1件も見つからなかったとき, the 網羅性検証 shall 検証した言語の数とキーの数を添えて、問題がない旨を報告する
7. The 網羅性検証 shall 問題の有無を、後続の自動化（CI）から機械的に判定できる形で示す
8. When 言語ファイルが追加または削除されたとき, the 網羅性検証 shall 検証対象の言語の一覧を手作業で更新することなく、その時点の言語ファイルすべてを対象にする
9. The 網羅性検証 shall 1回の実行で見つかった問題をすべて報告し、最初の問題で打ち切らない

### Requirement 4: 検証の運用上の位置づけ

**Objective:** As a 開発者, I want 検証がビルドや移行の妨げにならないこと, so that 翻訳を後回しにした作業や .NET 10 への移行を止めずに品質を保てる

#### Acceptance Criteria

1. While 言語ファイルに欠落やずれがある, the Large Folder Finder shall アプリのビルドを失敗させない
2. The 網羅性検証 shall テストの基盤が整っていない現時点の開発環境で実行できる
3. The 網羅性検証 shall .NET 10 への移行後も、検証の判定規則を作り直すことなく利用し続けられる
4. The 網羅性検証 shall 検証の実行によって言語ファイルおよびアプリの成果物を変更しない

### Requirement 5: 宣言コメントの実態への一致

**Objective:** As a 開発者, I want キー定義の説明が実際の仕組みと一致していること, so that キーを追加するときに誤った手順（順序合わせ）に従わず、必要な手順（全言語への追加と検証）を踏める

#### Acceptance Criteria

1. The Large Folder Finder shall `LanguageKey` の宣言の説明から、言語ファイルとの順序の一致を求める記述を取り除く
2. The Large Folder Finder shall `LanguageKey` の宣言の説明に、キーは名前で引かれること、キーを追加したら全言語のファイルに訳文を加えること、および網羅性検証で確かめられることを記す

### Requirement 6: 既存の挙動の維持

**Objective:** As a 利用者, I want 翻訳の修正によって言語の選択や表示の仕組みが変わらないこと, so that これまでどおりの操作で使い続けられる

#### Acceptance Criteria

1. The Large Folder Finder shall 言語ファイルの読み込み、OS の言語設定からの初期言語の選択、訳文が見つからないときの英語への置き換えの挙動を変えない
2. The Large Folder Finder shall 選択できる表示言語の一覧を変えない
3. The Large Folder Finder shall Requirement 1 と Requirement 2 で扱う訳文以外の訳文を変更しない
