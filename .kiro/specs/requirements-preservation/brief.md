# Brief: requirements-preservation

## Problem

大幅なリファクタリングにあたり、開発者から「**私の要望だけは残しつつ**」という明確な要求がある。しかしその要望の記録は、旧 AI モデルが生成した設計ドキュメントとして `docs/` 配下の41フォルダに散在しており、**`.gitignore` の `/docs/` によって Git 管理外**に置かれている。

つまり現状、**要望の記録はこのマシン上の1つの写ししか存在しない**。失われれば、何のためにその実装がその形になっているのかを復元する手段がなくなる。リファクタリングでコードを大きく作り替える以上、コードから意図を読み取ることも難しくなる。

## Current State

- `docs/` 配下に41フォルダ。各フォルダは `implementation_plan.md` / `task.md` / `walkthrough.md` などで構成される
- 内容は機能単位（`TabbedInterface`、`Cache_Optimization`、`layout_switching_feature`、`Physical_Size` など）
- `.gitignore:68` の `/docs/` により Git 追跡外。バックアップも取られていない
- `.kiro/steering/` には product / tech / structure / performance の4本があるが、いずれも**現状のコードから読み取れる事実**を記述したもので、「なぜそうしたか」の要望レベルの経緯は含まれていない

## Desired Outcome

- 41フォルダのドキュメントから、**要望・仕様上の決定・その理由**が抽出され、`.kiro/steering/` 配下に保全されている
- リファクタリング中に「この挙動は変えてよいのか」を判断する根拠が参照できる
- 抽出結果が Git 管理下にあり、失われない

## Approach

`docs/` は Git 管理外のままとし（開発者の判断）、**要点を `.kiro/steering/` へ抽出**する。

41フォルダを機械的に全文転記するのではなく、steering の粒度方針（パターンと理由を残し、網羅的な列挙は避ける）に従って要約する。抽出の観点は以下。

- **利用者から出た要望そのもの**（「クリップボード出力に折りたたみを反映したい」など）
- **仕様上の決定と、その背景にある理由**（なぜ物理サイズを既定にしたか、なぜ閾値未満の枝を刈らずに保持する方針へ変えたか）
- **試して却下された案**（同じ失敗を繰り返さないため）
- **明示的な非目標**

既存の4本に無理に押し込まず、必要なら `decisions.md` のような新しいカスタムステアリングを起こす。

## Scope

- **In**:
  - `docs/` 配下41フォルダの棚卸しと分類
  - 要望・決定・理由の抽出と `.kiro/steering/` への保全
  - 既存 steering（product / tech / structure / performance）との重複排除と整合
  - 抽出元と抽出先の対応関係の記録（後から辿れるようにする）

- **Out**:
  - `docs/` 自体の Git 管理下への移動（開発者の判断で管理外のまま）
  - ドキュメントの全文翻訳・全文転記
  - コードの変更

## Boundary Candidates

- 棚卸しと分類（どのフォルダに何が書かれているか）
- 要望・決定・理由の抽出
- steering への統合と重複排除

## Out of Boundary

- 実装の変更（本スペックはドキュメント作業に徹する）
- 抽出した要望が現在のコードと食い違っていた場合の修正（**食い違いは記録するにとどめ**、修正するかどうかは該当する後続スペックの判断に委ねる）

## Upstream / Downstream

- **Upstream**: なし（最初に着手できる）
- **Downstream**: 全スペックが参照する。特に `scan-correctness` と `ui-redesign` は「この挙動は仕様か不具合か」の判断でこの成果に依存する

## Constraints

- **`docs/` は要望の記録の唯一の写しである。** 作業中に破壊しないこと。読み取り専用として扱う
- steering の粒度方針に従うこと（`.claude/skills/kiro-steering/rules/steering-principles.md`）。網羅的な列挙ではなくパターンと理由を残す
- 1ファイル100〜200行程度を目安とし、単一のトピックに絞ること
- 旧 AI モデルが生成したドキュメントであるため、**記述が実際のコードと食い違っている可能性がある**。コードで確認できた事実と、ドキュメントにしか書かれていない意図とを区別して記録すること
- 機密情報（パス、個人名を含む実データなど）を steering に持ち込まないこと
