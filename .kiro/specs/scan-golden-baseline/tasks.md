# Implementation Plan

- [ ] 1. 基盤: 検証ツールの土台を用意する

- [ ] 1.1 検証ツールを独立した実行ファイルとして追加し、本体のビルドから分離する
  - 被テストアプリを参照する独立したコンソールアプリケーションを追加する。本体と同じ実行基盤を対象とする
  - 本体プロジェクトのソース収集設定に、新規ツールの配置先を除外指定として追加する。既に同種の除外指定が存在するため同じ形式に合わせる
  - ソリューションに新規プロジェクトを登録する
  - 生成されるフィクスチャの実体をバージョン管理の対象外にする。期待値データの置き場は追跡対象として残す
  - 外部パッケージに依存しない自己検証の土台を用意する。条件の成否を判定して集計し、失敗した項目を一覧できる最小限の仕組みとする
  - 自己検証をまとめて実行する経路を設け、失敗があれば非ゼロの終了コードを返す
  - 観測可能な完了状態: 本体と検証ツールの両方が個別にビルドでき、本体の出力アセンブリに検証ツールのソースが含まれていない。あわせて、意図的に失敗する検証項目を1つ置いた状態で自己検証を実行すると、その項目が失敗として報告され非ゼロの終了コードが返る
  - _Requirements: 2.1_

- [ ] 1.2 期待値データの表現を定義する
  - 1エントリを、基準からの相対パス・種別・バイト単位のサイズの3項目で表す。更新日時と所有者は項目として持たせない
  - 走査条件のメタデータとして、形式のバージョン、基準の論理名、生成日時、物理サイズ換算の有無、換算に用いたクラスタサイズ、フィクスチャの完全性と未生成項目を表す
  - サイズは64ビット整数で保持し、表示単位への変換を行わない
  - 観測可能な完了状態: 期待値データを表す型が定義され、更新日時と所有者を保持する手段が型として存在しない
  - _Requirements: 1.1, 1.2, 1.5, 2.5, 3.7, 6.1, 6.4_

- [ ] 1.3 拡張長パスへの変換を単一の箇所に用意する
  - 絶対パスへ正規化したうえで拡張長プレフィクスを付与する。正規化が後になると付与が無効になるため順序を守る
  - ネットワークパスの場合の形式に対応する。既に拡張長形式である場合は二重に付与しない
  - この変換以外の箇所が拡張長パスを扱わないようにする
  - 観測可能な完了状態: 260文字を超えるフォルダを作成でき、変換を通さない場合は作成に失敗することが確認できる
  - _Requirements: 3.1, 3.2_

- [ ] 2. 中核: 期待値の永続化と突き合わせ

- [ ] 2.1 (P) 期待値データの読み書きを実装する
  - エントリを相対パスの序数比較で昇順に並べる。カルチャ依存の比較を用いない
  - 出力の文字符号化と改行を固定し、数値を不変表記で桁区切りなしに出力する
  - ヘッダ部とエントリ部を持つ行指向の形式とし、人間が差分ツールで読める表記にする
  - 形式のバージョンを保持し、読み取り時に未知のバージョンを検出して失敗させる
  - 区切り文字がパスに含まれる場合を検出して失敗させる
  - 被テストアプリの型やシリアライズ実装を一切参照しない
  - 観測可能な完了状態: 同一の期待値データから常に同一のバイト列が出力され、書き出したファイルを読み戻すと等価な内容が得られる
  - _Requirements: 1.3, 1.4, 1.6, 7.2, 7.3, 7.4_
  - _Boundary: GoldenSerializer_

- [ ] 2.2 (P) 期待値と実測の突き合わせと差分の分類を実装する
  - 突き合わせの前に走査条件を照合し、物理サイズ換算の有無が異なる場合は突き合わせを行わずに設定不一致として報告する
  - 差分をサイズ不一致・欠落・新規・種別不一致の4種に分類する。サイズ不一致では期待された値と実際の値の双方を示す
  - 差分がない場合も明示的に一致として報告する
  - 判定結果と差分の全件を保持する結果表現を用意する
  - 観測可能な完了状態: 4種の差分をそれぞれ含む入力に対して、分類された差分が正しく列挙され、差分のない入力では一致と判定される
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 6.2, 6.3_
  - _Boundary: BaselineComparer, DiffReport_

- [ ] 3. 中核: フィクスチャの定義と生成

- [ ] 3.1 (P) フィクスチャの宣言的定義を用意する
  - 生成すべき項目を、相対パス・種別・内容のサイズ・境界条件の種類とともに宣言的に列挙する
  - 親フォルダが必ず定義に含まれ、相対パスが一意であることを保つ
  - この定義が「何が存在するはずか」の真値となり、既知の欠落を導出する根拠になる
  - 境界条件として、長いパス・日本語・空・サイズゼロ・アクセス拒否を区別できるようにする
  - 観測可能な完了状態: フィクスチャの内容が手続きではなくデータとして表現され、同じ定義から常に同じ構造が導かれる
  - _Requirements: 3.5, 5.2_
  - _Boundary: FixtureSpec_

- [ ] 3.2 (P) 読み取りを拒否するフォルダの作成と解除を実装する
  - 実行ユーザー自身に対する拒否設定を付与する。管理者権限を必要としない方法で行う
  - 解除の手段を必ず提供する。付与していないフォルダに対して解除を呼んでも安全に動作させる
  - 実行基盤の移行でアクセス制御の呼び出し方が変わるため、その差分をこの箇所の内側に閉じ込める
  - 観測可能な完了状態: 付与後は当該フォルダの列挙が拒否され、解除後は再び列挙できる
  - _Requirements: 3.4_
  - _Boundary: AccessControlGate_

- [ ] 3.3 フィクスチャの生成と後始末を実装する
  - 生成は拡張長パスへの変換を通した経路でのみ行う
  - フォルダとファイルで文字数の境界が異なるため、両方の境界をまたぐ構造を含める。長さは文字数で数える
  - 日本語を含む名前、空のフォルダ、サイズゼロのファイルを生成する
  - 一部が生成できなかった場合も中断せず、項目と理由を結果に含めて継続する
  - 後始末は拒否設定の解除と削除の2段階で行う。1段階では削除が失敗する。部分的に失敗した生成の後でも後始末を呼べるようにする
  - 観測可能な完了状態: 定義どおりの構造が生成され、後始末の実行後に残留物がない
  - _Requirements: 3.1, 3.2, 3.3, 3.5, 3.6_
  - _Depends: 1.3, 3.1, 3.2_
  - _Boundary: FixtureBuilder_

- [ ] 4. 中核: 走査の実行と期待値への射影

- [ ] 4.1 (P) 固定条件での走査実行を実装する
  - 抽出サイズの閾値をゼロ、ファイル表示を有効として走査する。表示条件を一切適用しない
  - 物理サイズ換算の有無を明示的に指定し、適用したクラスタサイズを結果に含める
  - アクセスできずスキップされた対象を記録する
  - 走査結果に手を加えない。欠落を補完せず、正しさの判定も行わない
  - 被テストアプリの内部に触れる面をこの箇所に限定する
  - 観測可能な完了状態: 同一のディスク状態に対して繰り返し実行しても同一の集計結果が得られ、スキップされた対象が結果から確認できる
  - _Requirements: 2.2, 2.3, 2.4, 5.1, 5.5, 6.1, 6.4_
  - _Boundary: ScanRunner_

- [ ] 4.2 走査結果を期待値データへ射影する
  - 基準からの相対パスを組み立て、区切りを統一する
  - サイズはバイト値をそのまま採り、整形経路を通さない
  - 更新日時と所有者を射影の対象に含めない
  - 走査結果を表す型が 4.1 の境界内で定義されるため、4.1 の完了を待つ。見た目は独立しているが並列実行の候補にはしない
  - 観測可能な完了状態: 走査結果ツリーから、重複のない相対パスを持つ期待値データが得られる
  - _Requirements: 1.1, 1.2, 5.1_
  - _Depends: 4.1_
  - _Boundary: GoldenProjector_

- [ ] 4.3 (P) 既知の不具合に由来する欠落を識別する
  - フィクスチャの宣言的定義が持つ真値と、走査で観測されたエントリを突き合わせる
  - 欠落した項目が持つ境界条件を根拠として、既知の不具合に由来するかを判定する
  - 手作業の注釈に頼らず、フィクスチャの変更に自動的に追随させる
  - 観測可能な完了状態: 長いパスの項目が観測されなかった場合に、その境界条件を理由として既知の欠落として列挙される
  - _Requirements: 5.2_
  - _Depends: 3.1_
  - _Boundary: KnownIssueAnalyzer_

- [ ] 5. 統合: 実行入口の配線と初回の期待値生成

- [ ] 5.1 サブコマンドと終了コードを配線する
  - フィクスチャの生成、期待値の生成、比較、期待値の更新の4つの実行を提供する
  - 基準パス、期待値ファイルの位置、物理サイズ換算の指定を入力として受け取り、検証する
  - 判定結果を終了コードで示す。一致、差分あり、設定不一致および実行時エラーを区別する
  - フィクスチャの生成を単独で実行した場合も、未生成の項目とその理由を一覧として標準出力へ報告する
  - 既知の欠落の識別結果は期待値の生成の報告に含める。独立したサブコマンドとしては公開しない
  - 期待値ファイル以外の副作用を残さない。フィクスチャは実行の最後に必ず後始末する
  - 観測可能な完了状態: 4つの実行がいずれも完走し、一致・差分あり・エラーのそれぞれで異なる終了コードが返る
  - _Requirements: 2.1, 3.6, 4.1, 4.7_
  - _Depends: 2.1, 2.2, 3.3, 4.1, 4.2, 4.3_

- [ ] 5.2 期待値の更新経路を実装する
  - 期待値を再生成する前に、現行の期待値との差分を提示する
  - 更新前後の差分を開発者が確認できる状態にする
  - 観測可能な完了状態: 更新の実行時に、現行の期待値と新しい結果の差分が提示されたうえで書き換えが行われる
  - _Requirements: 5.3, 5.4_
  - _Depends: 5.1_

- [ ] 5.3 フィクスチャに対する初回の期待値を生成して記録する
  - フィクスチャを生成し、固定条件で走査し、期待値データを書き出してバージョン管理下に置く
  - 未生成の項目があった場合、その事実を期待値データに残す
  - 観測可能な完了状態: 期待値データのファイルが生成され、同じ手順を繰り返しても内容がバイト単位で変わらない。あわせて標準出力に既知の欠落の一覧が、対象の相対パスと根拠となる境界条件の組として出力される
  - _Requirements: 2.1, 3.7, 5.1, 5.2, 7.1_
  - _Depends: 5.1_

- [ ] 6. 検証: 境界条件と回帰検出の確認

- [ ] 6.1 (P) 変換と永続化の単体検証を行う
  - 拡張長パスへの変換が、相対表記・既に拡張長形式のパス・ネットワークパスのそれぞれに対して正しい形式を返すことを確認する
  - 期待値の書き出しが、入力の順序を変えても同一のバイト列を生成することを確認する
  - 未知の形式バージョンの読み取りが拒否されることを確認する
  - 手書きの期待値ファイルが読み込めること、および読み書きの経路が被テストアプリの型に依存していないことを確認する
  - 観測可能な完了状態: 上記の確認がすべて再現可能な手順として実行でき、期待どおりの結果になる
  - _Requirements: 1.3, 2.3, 3.1, 7.2, 7.3_
  - _Boundary: LongPath, GoldenSerializer_

- [ ] 6.2 (P) 突き合わせの分類と設定不一致の単体検証を行う
  - サイズ不一致・欠落・新規・種別不一致の4種が正しく分類されることを確認する
  - 物理サイズ換算の設定差が、突き合わせの前に検出されることを確認する
  - 観測可能な完了状態: 4種の差分と設定不一致のそれぞれについて、期待どおりの判定結果が得られる
  - _Requirements: 4.2, 4.3, 4.4, 4.5, 6.2, 6.3_
  - _Boundary: BaselineComparer_

- [ ] 6.3 境界条件の欠落が既知の不具合として識別されることを確認する
  - フォルダとファイルのそれぞれの文字数境界を超える項目が、現行版の走査では観測されないことを確認する
  - それらが既知の欠落として識別され、根拠となる境界条件とともに把握できることを確認する
  - 日本語を含む長いパスについても同様に確認する
  - 観測可能な完了状態: 境界を超える項目の欠落が識別結果に列挙され、現行版の挙動として記録されている
  - _Requirements: 3.1, 5.1, 5.2_
  - _Depends: 5.3_

- [ ] 6.4 アクセス拒否時の継続と後始末を確認する
  - 読み取りを拒否するフォルダが走査でスキップされ、走査自体は完了することを確認する
  - スキップされた対象が記録されることを確認する
  - フィクスチャの一部が生成できなかった場合に、期待値へ不完全である旨が記録されることを確認する
  - 拒否設定を含むフィクスチャが残留なく削除されることを確認する
  - 観測可能な完了状態: 拒否設定のあるフィクスチャで生成から後始末までが完走し、実行後にディスク上に残留物がない
  - _Requirements: 2.4, 3.4, 3.6_
  - _Depends: 5.3_

## 意図的に後続へ委ねる検証

- 要件 7.1 のうち「異なる実行基盤をまたいだ再利用」の確認は、本スペックでは実行基盤が1つしか存在しないため完結できない。形式が実行基盤に依存しないことの確認は 6.1 で行い、実際に移行前の期待値データを移行後の比較で用いる検証は `dotnet10-migration` で実施する

## Implementation Notes

- テストフレームワークの導入は本スペックの対象外（`dotnet10-migration` の範囲）だが、テスト先行で実装を進める土台が必要なため、外部依存を持たない自己検証ハーネスをタスク1.1の土台に含めることとした。承認済みの範囲境界（外部のテストフレームワークを導入しない）は維持している。タスク6.1・6.2 はこのハーネスに具体的な検証項目を積む形で実装し、移行後に xUnit v3 へ引き上げる
