- [ ] 2. 走査の正しさ
- [ ] 2.1 事前カウントを、本スキャンと同じ集合を数える BCL の列挙に置き換える
  - 先に、フィクスチャを深さの上限6で本体の事前カウントに数えさせ、フィクスチャの仕様から導いたフォルダ数（ASCII と日本語の長い連鎖の全階層を含む）と比べる項目を自己検証に加え、置き換えの前に不一致になることを確かめる（RED）。本体に触れる呼び出しは検証ツールの走査の層に置く
  - RED は実行環境（レジストリの長いパスの設定、検証ツールの実行ファイルの長いパスの宣言）に左右されうる。その値と RED の結果（数の差）を Implementation Notes に記録する。再現しない場合は理由を記録し、置き換えの後の一致だけで判定する
  - 起点を深さ0として1と数え、深さの上限まで潜る意味を保つ。リパースポイントは除き、隠し・システム属性のフォルダは数え、アクセスできないフォルダは自身を数えて配下は数えない。各階層で取り消しを確かめる。走査の入口の公開の形は変えない
  - 手書きの OS 呼び出しによる旧来の事前カウントの処理を削除する
  - 完了の状態: 追加した項目が一致として通り、全テストが通り、期待値データとの比較が差分なしのまま
  - _Requirements: 1.1, 1.2, 1.5, 2.1, 2.3_

- [ ] 2.2 走査中のスキップを種類つきで集め、走査の終わりに1回で記録する
  - ファイルとフォルダの列挙の失敗を、アクセス拒否・見つからない・入出力の失敗に限って捕まえて記録する。捕まえた後の動き（そのフォルダの残りを飛ばして続ける）は変えない
  - それ以外の例外は捨てずに、走査の想定外の失敗として上に伝える（既存の、状態表示に内容を出してログに記録する経路に乗る）
  - 完了・取り消し・中断のいずれでも、スキップの件数と全件を1回でログに書く
  - 記録の一覧を検証ツールから確かめるのは、一覧が進捗の報告に載る 2.3 で行う
  - 完了の状態: ビルドが警告なしで通り、全テストが通り、期待値データとの比較が差分なしのまま
  - _Requirements: 2.3, 5.3, 5.6_

- [ ] 2.3 走査の正常な完了時に最後の進捗を1回報告し、事前カウントとの一致を確かめる
  - 正常に完了したときに、完了の印・最後の数・スキップの一覧を載せた進捗を1回だけ報告する。途中の通知の間隔（報告5秒・ログ20秒）は変えない
  - 検証ツールの走査の層で最後の進捗を受け取れるようにし、深さの上限3と6のそれぞれで、事前カウントの数と最後の報告の数が一致する（アクセス拒否のフォルダを含む）ことを確かめる項目を加える
  - アクセス拒否のフォルダを含むフィクスチャを走査し、そのパスが最後の報告のスキップの一覧にアクセス拒否として入り、走査が完了することを確かめる項目を加える
  - 完了の状態: 追加した項目が通り、全テストが通る
  - _Requirements: 1.4, 1.5, 3.4, 5.3_

- [ ] 2.4 使われていない OS 呼び出しの宣言を除き、残す宣言の説明を実態に合わせる
  - 事前カウント用の宣言（検索の開始・次・終了とその構造体・定数・列挙）と、使われていないウィンドウの表示と圧縮後のサイズの宣言を除く
  - クラスタサイズの取得とメモリの切り詰めの宣言は残し、クラスの説明をこの2つだけを持つ旨に改める
  - 本体の OS 呼び出しの宣言の型に除いた宣言が無いことを、反射で確かめる項目を自己検証に加える
  - 完了の状態: その項目が通り、ビルドが警告なしで通る。物理サイズ換算ありで走査し、1.1 で控えた期待値と差分がない

  - 完了の状態: その項目が例外なく通る。例外が出た場合は、本体の読み取りの規約の不備として直してから通す

- [ ] 2.6 最新の要求だけを有効にする取り消しの部品を作り、タブのデータに持たせる

  - 2回目の開始で1回目が取り消され最新でなくなること、別のインスタンスが互いに影響しないこと、まとめての取り消しの後は最新の通知も取り消されることを確かめる項目を自己検証に加える
  - タブのデータを保存して読み戻し、この部品が保存されず、読み戻した後も使える状態（null でない）であることを確かめる項目を加える

- [ ] 2.7 `Config.txt` の解析の失敗を記録して保持し、保存の失敗も記録する

  - 試験のために読み込み元のパスを指定できる入口を足す（既定の読み込みはそれを既定のパスで呼ぶ）
  - 壊れた内容の一時ファイルを読ませ、既定の設定が返ること、理由が保持されること、未通知の失敗が一度だけ取り出せることを確かめる項目を自己検証に加える（利用者の `Config.txt` には触れない）
